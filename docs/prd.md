# PRD: FileExplorer — 멀티 분할 경량 파일 탐색기

작성일: 2026-07-23
상태: 승인됨 (2026-07-23)

## 목적

Windows 11 이상에서 하나의 창을 여러 패널로 자유 분할하고, 각 패널이 독립 탭을 가지는 **경량 파일 탐색기**. Q-Dir의 멀티 패널 개념 + VS Code의 자유 분할 UX를 결합한다. 개발 언어는 Rust, 개인 사용 목적.

UI는 **egui(eframe/glow)** 로 그리고, 셸 연동(시스템 아이콘·컨텍스트 메뉴·디렉터리 변경 감시·파일 실행)은 windows-rs로 유지한다. 시작 속도는 네이티브 수준을 유지하되(NFR-1), 메모리는 GUI 프레임워크의 바닥값을 감안한 기준을 쓴다(NFR-2 — 2026-07-26 결정 이력 참조).

## 기능 요구사항 (Functional Requirements)

| ID | 요구사항 | 우선순위 | 검증 방법 |
|----|---------|---------|----------|

| FR-9 | 폴더 트리를 패널별로 토글 표시한다 (지연 확장 방식) | Should | HUMAN-VERIFY (트리 노드 열거 로직은 단위테스트) |
| FR-10 | 표시 중인 폴더의 변경(생성·삭제·이름변경)을 자동 새로고침한다 (`ReadDirectoryChangesW`) | Should | 통합테스트: 임시 폴더에 파일 생성 → 목록 갱신 이벤트 수신 검증 |
| FR-11 | 종료 시 분할 레이아웃·탭·창 위치를 저장하고 재시작 시 복원한다 | Should | 단위테스트: 세션 직렬화/역직렬화 왕복 검증 + 복원 화면은 HUMAN-VERIFY |
| FR-12 | 기본 단축키를 지원한다 (Ctrl+T 새 탭, Ctrl+W 탭 닫기, Alt+←/→ 히스토리, F5 새로고침, Ctrl+\\ 오른쪽 분할, Ctrl+Shift+\\ 아래쪽 분할, **Ctrl+Alt+←/→/↑/↓ 네 방향 분할**) | Should | HUMAN-VERIFY |
| FR-13 | 숨김·시스템 파일 표시를 토글할 수 있다 | Could | 단위테스트: 필터 로직 검증 |
| FR-14 | 분할 프리셋 버튼(1 / 좌우2 / 상하2 / 4분할)으로 레이아웃을 한 번에 전환할 수 있다 (Q-Dir식, 트리 재구성 헬퍼) | Could | 단위테스트: 프리셋 → 트리 구조 검증 |
| FR-15 | 창을 좌측 워크스페이스 사이드 패널과 우측 탐색기 영역으로 분리한다. 목록 항목은 2줄(1줄 이름, 2줄 활성 탭 폴더 경로 자동 표시)이며 사이드바는 고정 다크 스타일로 그린다 | Must | 단위테스트: 항목 표시 문자열(이름·경로 축약) 생성 로직 검증 + 화면은 HUMAN-VERIFY |
| FR-16 | 사이드바 `+` 버튼 또는 메뉴 바에서 워크스페이스를 새로 만든다. 홈 폴더 1패널로 시작하고 이름은 "워크스페이스 N"으로 자동 부여된 뒤 즉시 인라인 편집 상태가 된다 | Must | 단위테스트: 워크스페이스 목록 모델 add → 항목 수·자동 이름 검증 + UI는 HUMAN-VERIFY |
| FR-17 | 워크스페이스 항목을 선택하면 우측 탐색기가 해당 워크스페이스 전용 화면으로 전환된다. 워크스페이스마다 분할 레이아웃·패널·탭·히스토리가 독립적이다 | Must | 단위테스트: 활성 전환 모델 검증 + 전환 화면·상태 유지는 HUMAN-VERIFY |
| FR-18 | 워크스페이스 이름 변경(F2·컨텍스트 메뉴), 삭제(마지막 1개는 삭제 불가), 드래그로 순서 변경을 할 수 있다 | Should | 단위테스트: 모델의 rename/remove/reorder 연산 검증 + 조작은 HUMAN-VERIFY |
| FR-19 | 사이드바를 접기/펼치기로 토글하고 스플리터 드래그로 폭을 조절할 수 있다 | Should | 단위테스트: 폭 클램프·접힘 상태 계산 검증 + 드래그는 HUMAN-VERIFY |
| FR-20 | 워크스페이스 목록·활성 워크스페이스·사이드바 상태(폭·접힘)를 세션에 저장하고 재시작 시 복원한다 (FR-11 확장, 스키마 v2 — 구버전 v1 파일은 기존 규칙대로 초기화 폴백) | Should | 단위테스트: v2 세션 직렬화/역직렬화 왕복 + v1 파일 폴백 검증 |
| FR-21 | 탐색기 영역(파일 목록·폴더 트리·주소창·탭·**타이틀바(FR-22의 자체 렌더)**·메뉴바)을 고정 다크 스타일로 표시한다. 테마 전환 UI는 없다(사이드바 FR-15와 정합) | Should | 코드 확인(다크 팔레트 배선) + 화면은 HUMAN-VERIFY |
| FR-22 | 창 제목 표시줄을 OS 기본 장식 대신 **앱이 직접 그린다**. 좌측에 워크스페이스 사이드바 표시 토글, 중앙에 활성 워크스페이스 이름, 우측에 설정 메뉴(설정·업데이트·릴리즈 노트·오픈소스 라이선스·정보 — v1은 항목 표시만 하고 각 기능은 미구현)와 최소화·최대화·닫기 버튼을 둔다. 타이틀바 끌어 창 이동, 더블클릭 최대화, 가장자리 크기 조절을 지원한다 | Should | 단위테스트: 가장자리 방향 판정 로직 검증 + 화면·창 조작은 HUMAN-VERIFY |

우선순위: Must(없으면 미완성) / Should(중요하나 1차 출시 후 가능) / Could(여유 시)

## Out of Scope (명시적 제외)

- 자체 파일 작업 UI (복사/이동/삭제 진행률 창 — v1은 셸 컨텍스트 메뉴에 위임)
- 드래그 앤 드롭, 잘라내기/붙여넣기 자체 구현
- 파일 검색, 이름 필터
- 테마 전환 UI(라이트↔다크 토글·설정) — 사이드바·탐색기의 고정 다크 스타일은 FR-15·FR-21에 포함(전환 UI 없음). 커스텀 다크 스크롤바도 제외(시스템 제약)
- 즐겨찾기
- 셸 네임스페이스 가상 폴더 (휴지통·제어판·네트워크 위치 등 — 파일시스템 경로만 지원)
- 다국어 리소스 (v1은 한국어 고정)

## 성공 기준

- Must 요구사항(FR-1~FR-8, FR-15~FR-17) 100% 충족
- Should(FR-9~FR-12, FR-18~FR-22) 80% 이상
- NFR-1~NFR-3 실측 통과 (시작 1초·메모리 150MB·10만 파일 무정지)

## 결정 이력

- 2026-07-29: **커스텀 타이틀바 도입**(FR-22 추가, FR-21 표현 정정, 사용자 승인). 종전에는 OS가 그리는 제목 표시줄이라 그 안에 버튼을 둘 수 없었고, 사이드바를 접으면 다시 펴는 진입점이 메뉴·단축키뿐이었다. 창 장식을 끄고 타이틀바를 직접 그려 **사이드바 토글**과 **설정 메뉴**를 항상 보이는 자리에 둔다. 설정 메뉴의 5개 항목은 이번에 표시만 하고 기능은 후속 작업으로 미룬다. 대가로 **창 그림자·둥근 모서리와 Windows 11 스냅 레이아웃 팝업을 잃는다**(eframe이 winit의 무장식 그림자 확장에 접근 경로를 주지 않는다) — 드래그 스냅·Win+방향키·최대화 시 작업 표시줄 존중은 유지된다. 아이콘은 `egui-phosphor` 폰트를 쓴다(시스템 폰트 글리프 부재로 깨질 위험 없음).
- 2026-07-28: **분할을 네 방향으로 확장**(FR-1·FR-12 갱신, 사용자 승인). 종전에는 새 패널이 항상 오른쪽/아래에 생겨 왼쪽·위쪽에 두고 싶을 때 방법이 없었다. 진입점으로 **패널 탭 스트립 오른쪽 끝의 분할 버튼**(누르면 네 방향 메뉴)을 추가하고 보기 메뉴도 같은 네 항목으로 통일한다. 기존 `Ctrl+\\`·`Ctrl+Shift+\\`는 각각 오른쪽·아래쪽 분할로 **의미를 유지**하고 `Ctrl+Alt+방향키` 4종을 더한다(기존 단축키 제거 없음). 세션 스키마는 바뀌지 않는다 — 저장되는 것은 "어느 쪽에 넣었나"가 아니라 트리 구조(first/second) 자체라 왼쪽·위쪽 분할도 기존 v2로 표현된다.
- 2026-07-23: 분할 방식을 고정 프리셋이 아닌 **자유 분할(트리형)**로 확정 (사용자 선택). 프리셋은 Could(FR-14)로 격하.
- 2026-07-23: 언어 Rust(windows-rs), UI 한국어 고정, 설정 %APPDATA% 저장 확정 (사용자 선택).
- 2026-07-24: **워크스페이스 도입**(FR-15~FR-20·NFR-8 추가, 사용자 승인). Out of Scope의 "세션 프로필 다중 관리"를 철회해 요구로 채택하고, "다크 모드·테마"는 *앱 전체 테마 전환 기능* 제외로 한정(사이드바 고정 다크는 허용).
- 2026-07-24: 워크스페이스 세부 확정 (사용자 선택) — 항목은 이름+경로 2줄 / 관리 기능은 이름 변경·삭제·순서 변경 포함 / 사이드바는 이미지와 동일한 다크 카드 / 기존 v1 세션은 승격 없이 초기화 폴백 / 비활성 워크스페이스는 지연 생성 후 숨김 유지 / 명령 진입점은 사이드바 + 메뉴 바.
- 2026-07-26: **UI 프레임워크를 egui(eframe/glow)로 이식**(사용자 승인). 기능 요구(FR-1~FR-21)는 변경 없고, 구현 수단과 메모리 기준만 바꿨다 — **NFR-2 50MB → 150MB**, **NFR-8 100MB → 200MB**. 근거: PoC 실측에서 glow 백엔드의 최소 메모리가 131MB, 한글 폰트를 완전히 제외해도 100MB(eframe·winit·GL 컨텍스트 바닥값)였다. 50MB는 egui로 도달 불가능한 값이라 기준을 유지하면 이식이 정의상 실패한다. 대신 얻는 것: 콜드 스타트 47ms(현행 431ms), 다크 테마 완전 제어(FR-21의 Win32 best-effort 제약 해소), UI 코드 단순화. 잃는 것: 메모리 6배, exe 0.42MB → 약 10MB. 셸 연동(아이콘·컨텍스트 메뉴·감시)은 windows-rs 유지.
- 2026-07-24: **탐색기 전체 다크 테마 도입**(FR-21 추가, 사용자 승인). Out of Scope의 "앱 전체 다크 모드"를 *테마 전환 UI* 제외로 재한정하고, 탐색기 고정 다크(목록·트리·주소창·탭·타이틀바·메뉴바)를 요구로 채택. 메뉴바 팝업 배경은 Win32 제약상 best-effort. 함께 처리: 사이드바 크기 조절 잔상(배치 통합+더블버퍼링)·워크스페이스 폰트 확대·크기 조절 흰 깜빡임(WS_CLIPCHILDREN).
