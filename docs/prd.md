# PRD: FileExplorer — 멀티 분할 경량 파일 탐색기

작성일: 2026-07-23
상태: 승인됨 (2026-07-23)

## 목적

Windows 11 이상에서 하나의 창을 여러 패널로 자유 분할하고, 각 패널이 독립 탭을 가지는 **경량 파일 탐색기**. Q-Dir의 멀티 패널 개념 + VS Code의 자유 분할 UX를 결합한다. 개발 언어는 Rust, 개인 사용 목적.

UI는 **egui(eframe/glow)** 로 그리고, 셸 연동(시스템 아이콘·컨텍스트 메뉴·디렉터리 변경 감시·파일 실행)은 windows-rs로 유지한다. 시작 속도는 네이티브 수준을 유지하되(NFR-1), 메모리는 GUI 프레임워크의 바닥값을 감안한 기준을 쓴다(NFR-2 — 2026-07-26 결정 이력 참조).

### 원격 연결 (FTP/FTPS/SFTP) — 2026-08-04 추가

> 기준 문서: `docs/design/README.md`(디자인 명세 정본, High fidelity) + `docs/design/design-files/*.dc.html`.
> 원격 서버는 **별도 앱 모드가 아니라 패널의 한 종류**다 — 로컬 패널과 같은 화면 부품(ExplorerPane)이 원격 목록을 그린다.

| ID | 요구사항 | 우선순위 | 검증 방법 |
|----|---------|---------|----------|
| FR-27 | **사이트 관리자**로 원격 사이트를 등록·수정·삭제한다. '일반' 탭 필드는 프로토콜(T)·호스트(H)+포트(P)·암호화(E)·로그온 유형(L)·사용자(U)·비밀번호(W)이며, 좌측 목록은 루트 노드 없는 평면 목록 + `이름 바꾸기(R)`·`삭제(D)`·`복제(I)` 버튼. 바닥은 `연결(C)`(등록 후 즉시 연결)·`확인(O)`(등록만)·`취소` | Must | 단위테스트: 사이트 레코드 CRUD·중복 이름 회피 검증 + 화면은 HUMAN-VERIFY |
| FR-28 | 비밀번호는 **Windows DPAPI(`CryptProtectData`)로 암호화**해 저장한다. 평문은 어떤 파일·로그에도 남기지 않으며, 복호화 실패(다른 계정·다른 PC)는 "비밀번호 다시 입력"으로 폴백한다 | Must | 단위테스트: 암·복호 왕복 + 저장 파일에 평문 부재 검증 |
| FR-29 | 사이드바에 **연결 섹션**을 둔다 — 등록된 원격 사이트만 나열(로컬 경로는 워크스페이스 소관), 각 행은 상태 점·이름·프로토콜. 단일 클릭 선택 / **더블클릭 연결** / 우클릭 → 삭제(Del, 사이드바 바로가기만 제거하고 등록 사이트는 남긴다) / 헤더의 `+`는 연결 메뉴, `⟳`는 새로 고침 | Must | 단위테스트: 목록·숨김 사이트 분리 모델 검증 + 조작은 HUMAN-VERIFY |
| FR-30 | FTP·FTPS(명시적 TLS)·SFTP로 연결한다. 연결은 `연결 중 → 연결됨 / 실패` 3단계이며, 실패 시 패널에 **실패 화면**(서버 응답 문구·`재시도`·`설정 열기`·`서버 로그 보기`)을 띄운다 | Must | 통합테스트: 로컬 테스트 서버 대상 3프로토콜 연결·실패 분기 검증 |
| FR-31 | 원격 패널은 로컬과 **같은 부품**으로 그린다 — 탭 스트립·주소창·열 머리글·목록·상태 줄. 원격에만 **권한·소유자** 열을 더하고 열 메뉴에서 토글한다. `..` 항목은 항상 첫 줄, 심볼릭 링크는 이름 뒤에 `→ 대상`을 붙인다 | Must | 단위테스트: 원격 항목 정렬·열 구성 검증 + 화면은 HUMAN-VERIFY |
| FR-32 | 원격 탭은 **연결의 단위**다. 탭 라벨은 폴더 아이콘 → 프로토콜 배지 → 사이트 이름 → `✕` 순이며 배지는 단계별로 `sftp`/`ftps`/`ftp`(연결됨)·`연결 중…`·`연결 없음`으로 바뀐다. 연결 중에는 스켈레톤 8줄, 연결 없음 탭에는 안내 문구를 보인다. 마지막 탭을 닫으면 그 패널의 연결이 끊긴다 | Must | 단위테스트: 탭 단계 전이·배지 매핑 검증 + 화면은 HUMAN-VERIFY |
| FR-33 | 등록된 사이트가 하나라도 있으면 **모든 패널**(로컬·원격)의 탭 스트립에 사이트 드롭다운 `▾`를 보이고, 고른 사이트를 그 패널의 새 탭으로 연다 | Should | 단위테스트: 표시 조건·선택→탭 생성 매핑 검증 + 화면은 HUMAN-VERIFY |
| FR-34 | 원격 탭 주소창에 `sftp://호스트`(·`ftp://`·`ftps://`) 형식을 입력해 연결한다 | Should | 단위테스트: URL 파싱(프로토콜·사용자·호스트·포트·경로) 검증 |
| FR-35 | 사이트에 연결하면 **활성 패널을 좌우로 나눠 오른쪽에 원격 패널**을 만든다 — 로컬 원본이 원격 대상 바로 왼쪽에 오게 한다. 기존 분할 트리(FR-1)는 접지 않는다 | Should | 단위테스트: 연결 → 트리 구조(오른쪽 새 리프) 검증 |
| FR-36 | **전송 큐 패널**(하단 도킹, 접을 수 있음)에 전송을 나열한다. 열은 방향·로컬 파일·원격 파일·서버·크기·진행률·상태. 상단 탭은 `전송 큐 (N)`·`서버 로그`·`성공 (N)`·`실패 (N)`이며 성공·실패는 **같은 큐를 거르는 필터**다. 그 아래 연결별 탭(`전체` + 연결마다)으로 서버를 좁힌다 | Must | 단위테스트: 큐 모델·필터·집계 검증 + 화면은 HUMAN-VERIFY |
| FR-37 | 전송을 실행한다 — 사이트마다 **탐색용 연결 1 + 전송용 연결 2**를 두어 전송 중에도 폴더 이동이 막히지 않는다. 이어받기(FTP `REST` / SFTP 오프셋 열기), 전체 일시정지(`⏸`)·취소(`✕`), 실패 항목 재시도를 지원한다 | Must | 통합테스트: 테스트 서버로 업·다운로드·중단 후 이어받기 검증 |
| FR-38 | **로컬 패널과 원격 패널 사이에서 파일을 끌어다 놓아** 전송을 큐에 넣는다 (방향은 놓은 쪽이 정한다) | Should | HUMAN-VERIFY (큐 등록 로직은 단위테스트) |
| FR-39 | 원격 항목에 대해 **삭제·이름 바꾸기·새 폴더·권한 변경(chmod)** 을 한다. 삭제는 확인 대화를 거치고, 권한 변경을 지원하지 않는 FTP 서버(SITE CHMOD 미지원)에서는 사유를 알린다 | Should | 통합테스트: 테스트 서버로 각 작업 + 미지원 응답 처리 검증 |
| FR-40 | **서버 로그 패널**에 연결의 대화를 시각별로 남긴다 — 종류는 `상태:`·`명령:`·`응답:`·`오류:` 4종이며 종류별로 색이 다르다. 고정폭 글꼴로 그리고 비밀번호는 마스킹한다 | Should | 단위테스트: 로그 항목 생성·마스킹·링 버퍼 상한 검증 |
| FR-41 | 항상 보이는 **상태 표시줄**(30px)에 전송 큐 토글·큐 요약·전체 진행률 막대·현재 전송 파일·실패 알약(실패가 있을 때만)·연결 상태·로그 토글을 둔다 | Should | 단위테스트: 요약 문자열 생성 검증 + 화면은 HUMAN-VERIFY |
| FR-42 | 원격 패널에도 **폴더 트리**를 토글 표시한다 (지연 확장 — 펼칠 때 그 폴더를 한 번 조회하고 연결별로 캐시) | Should | 단위테스트: 확장 요청·캐시 적중 검증 + 화면은 HUMAN-VERIFY |
| FR-43 | 등록·삭제 같은 즉시 작업의 결과를 **토스트**로 알린다 (우하단, 3200ms 후 자동 소멸). 사이트 등록 시 문구는 `<host> 등록됨 · 더블클릭하여 연결` | Could | 단위테스트: 소멸 시각 계산 검증 + 화면은 HUMAN-VERIFY |
| FR-44 | 세션(스키마 v3)에 **사이트 목록·원격 탭·전송 큐·하단 패널 상태**를 저장하고 복원한다. 원격 탭은 사이트와 마지막 원격 경로만 기억해 **'연결 없음' 상태로 복원**하며 자동 재연결하지 않는다. 큐의 미완료·실패 항목은 복원하되 자동 재개하지 않는다 | Should | 단위테스트: v3 왕복 + v2 파일 승격 검증 |
| FR-45 | 사이트 관리자 **'전송 설정' 탭** — 전송 모드(`기본(E)`/`능동형(A)`/`수동형(P)`)와 `동시 연결 수 제한(L)` 체크 + `최대 동시 연결 수(M)` 값(1~10). 값은 실제 연결 동작에 반영된다 — 제한이 꺼져 있으면 FR-37의 기본(탐색 1 + 전송 2)을 쓰고, 켜져 있으면 **그 사이트의 전체 연결 수가 M을 넘지 않는다**(탐색용 1개를 먼저 확보하고 남는 수를 전송에 배정하며, M=1이면 한 연결로 탐색·전송을 번갈아 한다) | Should | 단위테스트: 설정 → 채널 배정 결과 검증(제한 꺼짐/M=1/M=3) |
| FR-46 | 사이트 관리자 **'문자셋' 탭** — `UTF-8(U)` / `문자셋 직접 설정(C)` 두 선택지와 `인코딩(E):` 필드(직접 설정일 때만 활성). 값은 원격 파일명 인코딩·디코딩에 반영된다 | Should | 단위테스트: 인코딩 왕복(비UTF-8 파일명 포함) 검증 |

우선순위: Must(없으면 미완성) / Should(중요하나 1차 출시 후 가능) / Could(여유 시)

## Out of Scope (명시적 제외)

- 자체 파일 작업 UI (복사/이동/삭제 진행률 창 — v1은 셸 컨텍스트 메뉴에 위임). 새 폴더·새 파일 만들기(FR-25)는 진행률이 필요 없는 즉시 작업이라 이 제외에 해당하지 않는다. **원격 전송의 진행률은 전송 큐(FR-36)가 담당하므로 이 제외에 해당하지 않는다**
- 목록에서 이름 바꾸기 인라인 편집 (새로 만든 항목도 기본 이름으로 두고, 이름 변경은 셸 컨텍스트 메뉴에 위임). **원격은 셸 메뉴를 쓸 수 없어 자체 이름 바꾸기를 둔다(FR-39) — 로컬 목록의 인라인 편집은 여전히 제외**
- 드래그 앤 드롭, 잘라내기/붙여넣기 자체 구현 — **단 로컬 패널↔원격 패널 사이의 전송 드래그(FR-38)와 사이드바 사이트→탭 드래그는 2026-08-04 결정으로 채택**했다. 로컬↔로컬 파일 이동·복사 드래그, OS(탐색기)와 주고받는 드래그, 잘라내기/붙여넣기는 계속 제외
- 파일 검색, 이름 필터
- 원격 관련 제외 (2026-08-04): SSH **키 파일·에이전트 인증**(v1은 비밀번호 인증만 — 로그온 유형은 `익명`·`일반` 2종), 프록시·SOCKS 경유 접속, 로컬↔원격 **폴더 동기화·비교·미러링**, 원격 파일을 열어 편집 후 자동 업로드, 원격 **썸네일**(파일을 통째로 받아야 해 비용이 맞지 않는다 — 원격은 형식 아이콘 고정), 원격 항목의 Windows 셸 컨텍스트 메뉴(셸은 로컬 경로만 다룬다), 사이트 설정의 가져오기/내보내기
- 테마 전환 UI(라이트↔다크 토글·설정) — 사이드바·탐색기의 고정 다크 스타일은 FR-15·FR-21에 포함(전환 UI 없음). 커스텀 다크 스크롤바도 제외(시스템 제약)
- 즐겨찾기
- 셸 네임스페이스 가상 폴더 (휴지통·제어판·네트워크 위치 등 — 파일시스템 경로만 지원)
- 다국어 리소스 (v1은 한국어 고정)

## 결정 이력

- 2026-08-04: **FTP/FTPS/SFTP 원격 연결 도입**(FR-27~FR-46·NFR-10~NFR-13 추가, Out of Scope 3건 재한정 + 원격 제외 8건 추가, 사용자 승인). 기준 문서는 `docs/design/README.md`이며 원격 서버를 **별도 모드가 아니라 패널의 한 종류**로 다룬다 — 로컬 패널과 같은 부품이 원격 목록을 그리므로 화면 규칙(정렬·열·탭·트리)이 갈리지 않는다. 사용자 확정 사항:
  - **프로토콜 3종 전부**(FTP·FTPS·SFTP). 라이브러리는 `suppaftp`(FTP/FTPS)·`ssh2`(SFTP)이며 **둘 다 동기(blocking) API**라 이 앱의 `std::thread` + 채널 구조에 그대로 맞는다(async 런타임을 들이지 않는다 — AGENTS 규약 유지). Windows에서 각각 schannel·WinCNG를 써 OpenSSL·perl 없이 빌드되는 것을 실제 컴파일로 확인했다.
  - **자격증명은 DPAPI 암호화 저장**(FR-28). FileZilla의 평문 저장 문제를 피하면서 디자인의 "더블클릭 → 즉시 연결"을 지킨다. 대가로 설정 파일을 복사해도 다른 PC·계정에서는 비밀번호가 풀리지 않는다.
  - **드래그 전송 채택**(FR-38) — Out of Scope의 "드래그 앤 드롭"을 *로컬↔로컬·OS 간 드래그* 제외로 재한정한다.
  - **원격 파일 작업은 chmod까지**(FR-39). 로컬은 셸 컨텍스트 메뉴에 위임하지만 셸은 원격 경로를 모르므로 자체 메뉴가 유일한 진입점이다.
  - **연결은 사이트당 탐색용 1 + 전송용 2**(FR-37). FTP는 한 연결에서 명령이 직렬로 흐르므로 나누지 않으면 큰 파일을 받는 동안 폴더 이동이 통째로 막힌다.
  - **재시작 시 자동 재연결 없음**(FR-44) — 시작하자마자 서버 여러 곳에 접속하면 콜드 스타트(NFR-1)가 네트워크에 묶이고, 서버가 꺼졌을 때 실패 화면으로 앱이 시작된다.
  - **자유 분할(FR-1)을 지킨다**(FR-35) — 디자인 원문은 "연결 시 기존 쌍을 첫 쌍으로 접고 쌍을 덧붙인다"이나 그대로 따르면 사용자가 짠 분할이 연결 한 번에 사라져 승인된 FR-1을 사실상 포기하게 된다. 대신 활성 패널을 좌우로 나눠 같은 목표("로컬 원본이 원격 대상 바로 왼쪽")를 달성한다.
  - **사이드바 폭**은 조절·저장(FR-19·FR-20)을 유지하고 기본값만 디자인 값(260px)으로 맞춘다 — 디자인의 260px 고정은 프로토타입 제약이며, 연결 섹션이 늘어 기본폭을 넓히는 것 자체는 타당하다.
