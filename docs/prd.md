# PRD: MOA — 멀티 분할 경량 파일 탐색기

작성일: 2026-07-23
상태: 승인됨 (2026-07-23)

## 목적

Windows 11 이상에서 하나의 창을 여러 패널로 자유 분할하고, 각 패널이 독립 탭을 가지는 **경량 파일 탐색기**. Q-Dir의 멀티 패널 개념 + VS Code의 자유 분할 UX를 결합한다. 개발 언어는 Rust, 개인 사용 목적.

UI는 **egui(eframe/glow)** 로 그리고, 셸 연동(시스템 아이콘·컨텍스트 메뉴·디렉터리 변경 감시·파일 실행)은 windows-rs로 유지한다. 시작 속도는 네이티브 수준을 유지하되(NFR-1), 메모리는 GUI 프레임워크의 바닥값을 감안한 기준을 쓴다(NFR-2 — 2026-07-26 결정 이력 참조).

| FR-4 | 파일 목록을 상세 보기(이름·크기·종류·수정일)로 표시하고 열 클릭으로 정렬한다. **열 경계를 드래그해 열 폭을 조절**할 수 있고(패널마다 독립·세션 저장), 머리글의 열 경계마다 **세로 구분선**을 두어 잡을 자리를 보이며 드래그 중에는 그 경계가 목록 바닥까지 강조색으로 이어진다. 열 폭 합이 패널보다 넓으면 **가로 스크롤**된다. 폭을 넘는 글자는 모든 열에서 `…`로 줄여 표시한다. **크기는 소수점 둘째자리 + KB/MB/GB 자동 승격**으로 적는다(`1.00 KB`·`1.18 MB`·`2.00 GB` — 0이 아닌 값은 최소 `0.01 KB`, 폴더는 빈 칸). 이 표기는 전송 큐·상태 표시줄과 **한 벌**이다 | Must | 단위테스트: 정렬 비교·열 폭 클램프 로직 검증 + 표시·드래그는 HUMAN-VERIFY |
| FR-5 | 파일·폴더에 시스템 아이콘을 표시한다 | Must | HUMAN-VERIFY (셸 이미지 리스트 연동 코드 확인 병행) |

| FR-8 | 우클릭 시 **Windows 11 탐색기와 같은 모양의 컨텍스트 메뉴를 앱이 직접 그린다** — 항목은 셸(`IContextMenu`)이 채운 것을 그대로 읽어 담으므로 설치된 셸 확장(압축·이름 바꾸기 도구 등)이 함께 나오고, 위쪽에 잘라내기·복사·이름 바꾸기·공유·삭제의 아이콘 줄을, 아래쪽 끝에 **`추가 옵션 표시`**를 둔다(그 줄이 종전의 Windows 표준 메뉴를 그대로 연다). **실제 파일 작업은 그대로 셸에 위임한다** — 복사·삭제·이름 바꾸기는 `IFileOperation`이, 나머지 항목은 `InvokeCommand`가 수행하므로 진행률·충돌·되돌리기 대화는 모두 OS의 것이다. 글자 없이 스스로 그리는 방식(owner-draw)을 쓰는 확장은 이름을 읽을 수 없어 그 줄이 빠질 수 있으며, 그런 항목도 `추가 옵션 표시`의 표준 메뉴에서는 정상으로 보인다 (2026-08-22 개정 — 종전 문면은 「Windows 셸 컨텍스트 메뉴를 표시한다」) | Must | 단위테스트: 메뉴 모델 변환(항목·구분선·하위 메뉴·비활성)·아이콘 줄 구성·verb 대응 검증 + 화면과 확장 항목 실행은 HUMAN-VERIFY |
| FR-9 | 폴더 트리를 패널별로 토글 표시한다 (지연 확장 방식). **로컬 트리의 모든 줄에는 셸 아이콘이 붙고**(드라이브는 드라이브 아이콘, 폴더는 그 폴더의 아이콘 — 원격 트리는 서버 아이콘을 얻을 수 없어 모두 같은 폴더 아이콘을 쓴다), **드라이브 줄은 `로컬 디스크 (C:)` 같은 셸 표시 이름**으로 보인다(이름을 얻지 못하면 경로 문자열로 폴백). **닿지 못하는 네트워크 드라이브 줄에는 아이콘 오른쪽 아래에 연결 끊김 표식(빨간 원 안의 흰 X)이 겹친다** — 탐색기와 같은 표시이며 누르기 전에도 보인다(로컬 드라이브와 닿는 네트워크 드라이브에는 두지 않는다). 그 판정은 시작할 때 한 번, 그리고 그 드라이브를 열어 볼 때 갱신된다 | Should | HUMAN-VERIFY (트리 노드 열거 로직은 단위테스트) |

### 원격 연결 (FTP/FTPS/SFTP) — 2026-08-04 추가

> 기준 문서: `docs/design/README.md`(디자인 명세 정본, High fidelity) + `docs/design/design-files/*.dc.html`.
> 원격 서버는 **별도 앱 모드가 아니라 패널의 한 종류**다 — 로컬 패널과 같은 화면 부품(ExplorerPane)이 원격 목록을 그린다.

| FR-30 | FTP·FTPS(명시적 TLS)·SFTP로 연결한다. 연결은 `연결 중 → 연결됨 / 실패` 3단계이며, 실패 시 패널에 **실패 화면**(서버 응답 문구·`재시도`·`설정 열기`·`서버 로그 보기`)을 띄운다 | Must | 통합테스트: 로컬 테스트 서버 대상 3프로토콜 연결·실패 분기 검증 |
| FR-31 | 원격 패널은 로컬과 **같은 부품**으로 그린다 — 탭 스트립·주소창·열 머리글·목록·상태 줄. 원격에만 **권한·소유자** 열을 더하고 열 메뉴에서 토글한다. `..` 항목은 항상 첫 줄, 심볼릭 링크는 이름 뒤에 `→ 대상`을 붙인다 | Must | 단위테스트: 원격 항목 정렬·열 구성 검증 + 화면은 HUMAN-VERIFY |
| FR-32 | 원격 탭은 **연결의 단위**다. 탭 라벨은 폴더 아이콘 → 프로토콜 배지 → 사이트 이름 → `✕` 순이며 배지는 단계별로 `sftp`/`ftps`/`ftp`(연결됨)·`연결 중…`·`연결 없음`으로 바뀐다. 연결 중에는 스켈레톤 8줄, 연결 없음 탭에는 안내 문구를 보인다. 마지막 탭을 닫으면 그 패널의 연결이 끊긴다 | Must | 단위테스트: 탭 단계 전이·배지 매핑 검증 + 화면은 HUMAN-VERIFY |
| FR-33 | **모든 패널**(로컬·원격)의 탭 스트립에서 `+`(새 탭)를 누르면 메뉴가 열리고, `새 탭` 아래에 **등록된 사이트 목록**(상태 점·이름·프로토콜)이 이어진다. 사이트 줄을 고르면 그 패널의 새 탭으로 연다. 등록된 사이트가 하나도 없으면 `새 탭` 한 줄만 남는다 (2026-08-19 개정 — 종전에는 `+` 옆의 `▾` 드롭다운이 그 목록을 열었다. 버튼 둘이 나란히 서면 무엇이 무엇인지 눌러 봐야 알 수 있어 진입점을 메뉴 하나로 합쳤다) | Should | 단위테스트: 사이트 유무별 메뉴 구성·선택→탭 생성 매핑 검증 + 화면은 HUMAN-VERIFY |
| FR-34 | 원격 탭 주소창에 `sftp://호스트`(·`ftp://`·`ftps://`) 형식을 입력해 연결한다 | Should | 단위테스트: URL 파싱(프로토콜·사용자·호스트·포트·경로) 검증 |
| FR-35 | 사이트에 연결하면 **활성 패널을 좌우로 나눠 오른쪽에 원격 패널**을 만든다 — 로컬 원본이 원격 대상 바로 왼쪽에 오게 한다. 기존 분할 트리(FR-1)는 접지 않는다 | Should | 단위테스트: 연결 → 트리 구조(오른쪽 새 리프) 검증 |
| FR-36 | **전송 큐 패널**(하단 도킹, 접을 수 있음)에 전송을 나열한다. 열은 방향·로컬 파일·원격 파일·서버·크기·진행률·상태. 상단 탭은 `전송 큐 (N)`·`서버 로그`·`성공 (N)`·`실패 (N)`이며 성공·실패는 **같은 큐를 거르는 필터**다. 그 아래 연결별 탭(`전체` + 연결마다)으로 서버를 좁히며, **그 탭의 건수는 지금 고른 필터를 따른다**(어느 서버가 탭에 서는지는 필터와 무관하다 — 그 필터에 항목이 없는 서버도 자리는 남는다. `서버 로그` 화면에서는 건수를 적지 않는다). **행 우클릭 메뉴는 그 행의 상태가 정한다** — 실패는 `다시 시도`·`전체 다시 시도`·`삭제`·`전체 삭제`, 끝난 것은 `삭제`·`전체 삭제`, 진행 중·대기는 `전송 취소`·`전체 삭제`(`전송 취소`와 `삭제`는 동작이 같아 한 쪽만 보이고, `전체 다시 시도`는 보이는 목록에 실패가 있을 때만 선다). `전체 …`의 대상은 **지금 보고 있는 목록**(상단 필터 ∩ 연결별 탭)이다. **열 폭은 경계를 끌어 조절**하고 세션에 저장한다 — 폭 합이 표보다 좁으면 마지막 `상태` 열이 잔여를 흡수하고, 넘으면 오른쪽이 잘린다(가로 스크롤 없음) | Must | 단위테스트: 큐 모델·필터·집계 검증 + 화면은 HUMAN-VERIFY |
| FR-37 | 전송을 실행한다 — 사이트마다 **탐색용 연결 1 + 전송용 연결 2**를 두어 전송 중에도 폴더 이동이 막히지 않는다. 이어받기(FTP `REST` / SFTP 오프셋 열기), 전체 일시정지(`⏸`)·취소(`✕`), 실패 항목 재시도를 지원한다. **전송이 끝나면 그 목적지 폴더를 보고 있는 원격 패널의 목록을 다시 읽는다** — 서버에는 변경 통지가 없어 앱이 스스로 다시 묻지 않으면 방금 올린 파일이 손으로 새로 고칠 때까지 보이지 않는다. 대상은 **그 사이트의 그 폴더**를 보는 패널이며(전송을 처리한 연결과 패널의 연결이 다를 수 있다), 여러 건이 끝나도 조회는 **사이트마다 대기·진행이 없어졌을 때 한 번**으로 합친다(오래 걸리는 전송은 그 사이에도 최소 간격을 두고 갱신한다) — 파일마다 다시 물으면 서버 왕복이 파일 수에 비례한다. 받기(다운로드)는 로컬 폴더 감시가 이미 갱신하므로 이 조회 대상이 아니다 | Must | 통합테스트: 테스트 서버로 업·다운로드·중단 후 이어받기 검증 + 단위테스트: 재조회 대상 선별(사이트·폴더 일치)·합치기 시점 검증 |
| FR-38 | **로컬 패널과 원격 패널 사이에서 파일을 끌어다 놓아** 전송을 큐에 넣는다 (방향은 놓은 쪽이 정한다). 대상에 같은 이름이 있으면 FR-55의 확인을 거친다. **끄는 동안에는 고른 것 중 첫 항목의 반투명 그림이 커서를 따라온다** — 이미 만들어져 있는 미리보기가 있으면 그것이고 없으면 그 파일의 형식 아이콘이다(원격 항목은 미리보기가 없어 언제나 형식 아이콘이다). 여러 개를 끌어도 **첫 항목 한 장**이며 개수 배지·이름 글자는 붙이지 않는다. 이 그림은 **앱 안에서 끄는 동안에만** 보이고 창 밖으로 나가면 셸이 그리는 그림(FR-61 ⓑ)으로 넘어간다. **로컬끼리의 복사 드래그(FR-60)도 같은 그림을 쓴다.** 그림을 얻지 못해도 끌기·전송은 그대로 된다 | Should | HUMAN-VERIFY (큐 등록 로직은 단위테스트, 미리보기 그림의 수명 판정은 단위테스트) |

| FR-60 | **로컬 패널끼리 파일·폴더를 끌어다 놓아 복사한다** — 로컬 탭에서 고른 것을 다른 로컬 탭(또는 같은 패널의 다른 폴더)에 놓으면 그 폴더로 복사된다. **끌어온 항목이 있던 폴더에 그대로 놓으면 아무 일도 하지 않는다** — 사본(`- 복사본`)을 만들지 않고 알림도 띄우지 않는다(탐색기와 같다). 판정은 **놓인 폴더가 같은가**로 하므로, 다른 탭이 우연히 같은 폴더를 보고 있을 때도 취소된다. **OS에서 끌어온 것(FR-61 ⓐ)은 이 판정 대상이 아니다** — 그 경로는 종전대로 셸이 복사한다. **동작은 언제나 복사다** — 보조키로 이동을 가르지 않으며 원본은 그대로 남는다. **복사 자체는 Windows 셸(`IFileOperation`)에 맡긴다** — 진행률 대화·같은 이름 충돌 대화·되돌리기(`Ctrl+Z`)·권한 승격이 OS의 것이며, 그래서 로컬끼리의 복사에는 FR-55의 자체 확인 대화를 띄우지 않는다(셸이 자기 대화로 묻는다). 셸이 오류를 주거나 사용자가 셸 대화에서 취소하면 그 사실을 상태 줄에 알린다 | Should | 단위테스트: 드롭 판정(로컬 항목 + 로컬 대상일 때만 복사 대상)·**같은 폴더 취소 판정**(대소문자만 다른 경로 포함)·알림 문구 생성 검증 + 실제 복사와 셸 대화는 HUMAN-VERIFY |

## 결정 이력

- 2026-08-22: **자동 업데이트와 릴리즈 노트 열기를 채택한다**(FR-62·FR-63 신설, Out of Scope 재한정). 원문: *"업데이트 기능 구현 … 릴리즈 노트 메뉴 클릭시 git 릴리즈 페이지 연결"*. **이 결정은 2026-08-21 이력의 「코드 서명·자동 업데이트는 범위 밖이다」를 뒤집는다** — 그 줄은 그 시점의 기록이라 그대로 두고, 지금부터의 정본은 이 줄이다(코드 서명은 계속 범위 밖). 사용자 확정 사항:
  - **확인은 앱 실행당 한 번, 설치본에서만** — 시작을 막지 않도록 워커에서 돌리고, 실행 파일 옆에 제거 프로그램이 없는 개발 실행에서는 확인조차 하지 않는다.
  - **받은 파일은 SHA256으로 검증한다** — 릴리즈 본문에 적힌 값과 어긋나면 지우고 멈춘다. 본문에 값이 없는 릴리즈는 받지 않는다.
  - **설치는 앞 화면을 건너뛴다** — 설치 프로그램에 업데이트 모드를 두어 언어·환영·라이선스·폴더 페이지 없이 진행 화면만 보이고, 끝나면 앱을 다시 띄운다.
  - **릴리즈 노트는 일반 사용자가 읽는 글이다** — 항목당 한두 줄, 내부 사정은 빼고, 길거나 어렵게 쓰지 않는다. 앱이 읽어야 하는 체크섬은 본문 맨 아래 접어 두어 그 원칙과 부딪히지 않게 한다.

Win11 모던 메뉴를 그대로 호스팅하는 공개 API는 없어(그 표면은 탐색기 프로세스 안에서만 산다) **항목만 셸에서 읽어 우리가 그리는** 방식으로 채택했고, 읽히지 않는 owner-draw 확장을 위해 `추가 옵션 표시`가 종전 표준 메뉴를 그대로 연다. Out of Scope 두 줄을 재한정한다 — **목록 인라인 이름 편집**(셸 `rename` verb는 탐색기 자신의 뷰가 처리하는 것이라 위임 대상이 애초에 없었다)과 **클립보드 잘라내기/붙여넣기**를 채택하고, 드래그 이동·원격↔원격 드래그·자체 진행률 창 제외는 그대로 둔다(작업은 `IFileOperation`이 하므로 진행률 창을 만들지 않는다). `F2`·`Delete`의 키 소유를 **마지막으로 조작한 영역**으로 정한 것은 사이드바가 키를 전역으로 보아 파일 목록의 키를 가로채던 문제(`docs/plans/deferred.md` 2026-07-28 등재)를 함께 푼다.
