# FTP/FTPS/SFTP 원격 연결 통합

**PRD**: docs/prd.md
**기준 문서**: docs/design/README.md (디자인 명세 정본) + docs/design/design-files/{FileExplorer-FTP,ExplorerPane}.dc.html + docs/design/screenshots/*.png

## 요구 이해

> 원문 요청: "docs\design 폴더를 문서를 확인해서 FTP 관련 디자인 확인해서 기능 구현
> 1. 현재 앱에 파일질라 같은 ftp 기능 추가.
> 2. ftp, 탐색기 기능 모두 멀티 스레드로 동작.
> 3. 동작 중 ui 프리징이 발생하면 안됨
> 4. 최적화 필수
> 5. ftp를 동시에 여러개를 연결해도 문제가 발생하지 않도록 함."

이해한 요구:

1. `docs/design/`의 디자인 문서(README + HTML 프로토타입 + 스크린샷)를 **기준**으로 삼아, 지금의 로컬 파일 탐색기에 **FileZilla급 원격 연결 기능**을 넣는다. 디자인의 핵심 개념은 "원격 서버는 별도 앱 모드가 아니라 **패널의 한 종류**"이므로, 지금의 `ExplorerPane`이 로컬과 원격을 **같은 부품으로** 그린다.
2. 새로 넣는 원격 기능뿐 아니라 **기존 탐색기 기능까지** 멀티스레드 원칙을 지킨다. 지금도 열거·감시·썸네일·생성은 워커 스레드지만, 원격이 들어오면 훨씬 느린 I/O가 섞이므로 **UI 스레드에서는 채널 폴링만** 한다는 규칙을 원격 전 경로로 확장한다.
3. 어떤 원격 작업(연결·인증·목록·전송·파일 작업) 중에도 창이 멈추지 않는다. 서버가 응답하지 않거나 네트워크가 끊겨도 다른 패널·다른 연결의 조작은 계속된다.
4. 최적화 — 전송은 스트리밍(파일을 통째로 메모리에 올리지 않음), 목록 파싱·정렬은 워커, 그리기는 가상 스크롤, 원격 트리·타입명은 캐시. 시작 속도(NFR-1)를 원격 기능이 끌어내리지 않는다(재시작 시 자동 재연결 없음).
5. 사이트를 **여러 곳 동시에** 연결해도 서로 간섭하지 않는다. 연결마다 독립 워커·상태·로그를 가지며, 한 연결의 지연·실패·재연결이 다른 연결이나 로컬 탐색을 멈추게 하지 않는다.

## Goal

디자인 문서에 정의된 원격 연결 화면 일습(사이드바 연결 섹션 · 원격 패널과 탭 단계 · 사이트 관리자 · 전송 큐 · 서버 로그 · 상태 표시줄 · 토스트 · 드래그 전송)을 FTP·FTPS·SFTP 3프로토콜 위에 구현하고, 모든 원격 I/O를 연결별 워커 스레드로 격리해 UI 프리징 0과 다중 연결 무간섭을 실측으로 보인다.

## Scope

- `src/remote/` 신설 — 원격 도메인 타입 · 프로토콜별 세션 · 연결 워커 · 연결 관리자 · 전송 실행기 · 서버 로그 · 자격증명 보관
- `src/ui/` 확장 — 연결 섹션 · 원격 탭 단계 화면 · 사이트 관리자 · 전송 큐/로그 패널 · 상태 표시줄 · 토스트 · 원격 열/트리/파일 작업 메뉴 · 드래그 전송
- `src/ui/panel.rs` 개편 — 탭이 **로컬 폴더 또는 원격 위치** 중 하나를 가리키도록 소스 추상화
- 세션 스키마 v2 → v3 (사이트 목록 · 원격 탭 · 전송 큐 · 하단 패널 상태)
- 의존성 추가: `suppaftp`(native-tls) · `ssh2` · `windows` 기능 `Win32_Security_Cryptography`

## Out of Scope

PRD `## Out of Scope`의 "원격 관련 제외 (2026-08-04)" 전부를 따른다 — SSH 키 파일·에이전트 인증(v1은 비밀번호 인증만, 로그온 유형은 `익명`·`일반` 2종), 프록시·SOCKS, 로컬↔원격 폴더 동기화·비교·미러링, 원격 파일 열어 편집 후 자동 업로드, 원격 썸네일, 원격 항목의 Windows 셸 컨텍스트 메뉴, 사이트 설정 가져오기/내보내기. 더해서:

- 로컬↔로컬 드래그(이동·복사)와 OS(탐색기)와 주고받는 드래그 — PRD Out of Scope 그대로 유지. 이번에 여는 것은 **로컬 패널↔원격 패널 사이의 전송 드래그**와 **사이드바 사이트→탭 드래그**뿐이다
- 디자인 문서의 `고급` 탭 — README §9가 "제거 대상"으로 명시
- 전송 큐 항목의 순서 변경(드래그로 재정렬)·우선순위 — 디자인에 진입점이 없다

## Deferred / Follow-up

이번 작업과 무관한 이전 plan의 잔여 항목은 `docs/plans/deferred.md`의 `## 대기`에 이미 옮겨져 있다. 이번 작업에서 새로 미루는 것:

- [ ] 사이트 관리자 `전송 설정`·`문자셋` 탭의 재디자인 반영 — README §9가 "재디자인 예정, 현재 HTML대로 만들고 변경을 예상하라"고 예고. 이번엔 HTML대로 만들고 기능까지 연결한다(사용자 확정)
- [ ] 원격 목록의 변경 감시(로컬 FR-10의 원격 판) — FTP·SFTP에 표준 통지 수단이 없어 폴링뿐이고, 폴링은 서버 부하·연결 점유가 커 이번엔 수동 새로 고침만 둔다
- [ ] 전송 큐 항목 재정렬·우선순위 (Out of Scope 사유와 같음 — 디자인에 진입점이 생기면 검토)
- [ ] **SFTP 로그인 실패 문구의 인증 방식 목록** (T3 quality 리뷰 m1) — `auth_error`가 `받는 방식: publickey,keyboard-interactive`처럼 SSH 프로토콜 식별자를 그대로 보인다. 주 문장("이 서버는 비밀번호 인증을 받지 않습니다")은 사용자 언어이고 그 목록은 사용자가 서버 관리자에게 전할 정보라 이번엔 그대로 뒀다 — 사용자 문구 다듬기를 검토한다
- [ ] **SFTP 목록의 비UTF-8 파일명** (T3 관측) — `ssh2`가 Windows에서 경로 바이트를 `from_utf8().unwrap()`으로 옮겨 **패닉**한다. 지금은 `guard_path_panic`이 오류로 바꿔 연결을 지키지만, CP949 서버의 파일명을 **읽어 보이는 것**은 못 한다(라이브러리 안에서 이름이 버려진다). 문자셋 지원(T16·D23)에서 이 경로를 어떻게 다룰지 정해야 한다
- [ ] **[SUGGEST] `remote::testing`이 릴리스 빌드에 포함된다** (T4 quality 리뷰 m2) — 가짜 서버·세션 400여 줄이 배포 exe에 그대로 들어간다. `tests/`가 라이브러리를 일반 빌드로 링크해서 `#[cfg(test)]`를 쓸 수 없기 때문이다. Cargo feature(`test-util`)로 가르는 것이 깔끔하지만 이 프로젝트에 feature 관례가 전혀 없어 이번엔 두었다 — T26에서 exe 크기를 잴 때 함께 판단한다
- [ ] 원격 목록 가상 스크롤의 원격 전용 튜닝 — 로컬과 같은 렌더 경로를 쓰므로 기본 성능은 따라오지만, 1만 항목 이상에서 재측정 후 필요하면
- [ ] **디자인 HTML의 샘플 호스트 값 — 사용자 판단 필요** (T0에서 관측). `docs/design/design-files/FileExplorer-FTP.dc.html`의 2곳(`:576`·`:1012`)에 실제 IP 형태의 샘플 호스트가 들어 있어 커밋 시 `check-secrets` hook이 경고했다. **사용자가 제공한 기준 문서라 임의 수정하지 않았고**(글로벌 지침 "요청하지 않은 부분은 수정하지 않는다"), 이 plan·PRD·notes 등 **내가 작성한 문서에는 옮기지 않았다**(시각 요소 분해에 `<호스트>`로 표기). 브랜치는 로컬이며 push는 별도 승인 대상이므로 아직 외부로 나가지 않았다 — **push 전에 그 값을 가릴지 사용자가 결정**하면 된다

## 사전 승인 항목 (일괄 승인 대상)

이 plan을 승인하면 아래는 그 지점에서 다시 묻지 않고 진행한다.

1. **의존성 추가(비파괴)** — `suppaftp = "10.0.1"`(features `native-tls`), `ssh2 = "0.9.6"`, 기존 `windows` 크레이트에 `Win32_Security_Cryptography` 기능 추가. 세 가지 모두 이번 계획 중 실제 빌드로 확인했다(Investigation Log 참조)

4. **로컬 작업 브랜치 commit** — 체크포인트 commit과 task 완료 commit
5. **테스트 추가** — 각 task의 Acceptance에 적힌 단위·통합 테스트
6. **문서 갱신** — `README.md`·`notes.md`·`AGENTS.md`(원격 모듈 구조·실서버 테스트 환경변수 사용법)

### 전제 검증

| # | 전제 | 확인 방법 | 결과 |
|---|------|----------|------|
| 1 | FTP/FTPS 클라이언트를 **동기 API**로 쓸 수 있다 (async 런타임 없이 — AGENTS "tokio 등 async 런타임 사용 안 함") | `cargo info suppaftp` + docs.rs + 스크래치 프로젝트 컴파일 | ✅ `suppaftp 10.0.1`은 `default-features = []`가 동기 `FtpStream`. `connect`/`login`/`cwd`/`pwd`/`list`/`mlsd`/`transfer_type`/`resume_transfer`/`retr`/`put_file`/`append_file`/`mkdir`/`rm`/`rmdir`/`rename`/`size`/`noop`/`quit` 전부 컴파일 확인 |
| 2 | FTP LIST 원문을 **파서 없이 직접 다루지 않아도** 된다 | 같은 컴파일 검증 | ✅ `suppaftp::list::File`이 `FromStr` — `name()`·`size()`·`is_directory()`·`is_symlink()`·`modified()`·`uid()`·`gid()`·`can_read(PosixPexQuery::Owner)` 제공. **권한·소유자 열(FR-31)의 원천이 여기다** |
| 3 | FTPS(명시적 TLS)를 **OpenSSL 없이** 쓸 수 있다 | `cargo add suppaftp --features native-tls` 후 빌드 | ✅ Windows에서 `schannel` 백엔드로 20초 빌드. `NativeTlsFtpStream::connect(..).into_secure(NativeTlsConnector::from(TlsConnector::new()?), host)` 컴파일 확인 |
| 4 | SFTP를 **동기 API + 추가 빌드 도구 없이** 쓸 수 있다 | `cargo add ssh2` 후 빌드 | ✅ `ssh2 0.9.6`(libssh2)이 Windows WinCNG 백엔드로 **19.26초 빌드 — OpenSSL·perl 불필요**. `Session::{new,set_tcp_stream,handshake,userauth_password,authenticated,sftp,set_blocking}` 확인 |
| 5 | SFTP 목록에서 크기·시각·소유자·권한을 **한 번에** 얻는다 (FTP처럼 별도 STAT 왕복이 필요하지 않다) | 같은 컴파일 검증 | ✅ `Sftp::readdir(&Path) -> Vec<(PathBuf, FileStat)>`이고 `FileStat`에 `size`·`mtime`·`uid`·`gid`·`perm`·`is_dir()`·`is_file()` |
| 6 | 전송 진행률을 **직접 셀 수 있다** (라이브러리가 콜백을 안 줘도) | 같은 컴파일 검증 | ✅ FTP는 `retr`가 리더를 콜백으로 넘겨주고 `put_file`이 임의 `Read`를 받는다. SFTP는 `Sftp::open`/`create`가 `std::io::Read`/`Write`. **양쪽 다 우리가 버퍼 단위로 읽고 쓰므로 진행률·스트리밍·취소를 직접 통제**한다 (NFR-12) |
| 7 | 이어받기(REST/오프셋)가 가능하다 | 같은 컴파일 검증 | ✅ FTP `resume_transfer(offset)`, SFTP `open_mode(path, OpenFlags, mode, OpenType)` |

## Decisions

| # | 결정 | 선택 | 근거(Source) |
|---|------|------|--------------|
| D1 | FTP/FTPS 라이브러리 | `suppaftp = "10.0.1"` (features `native-tls`) | 전제 1·2·3 — 동기 API로 현 스레드 구조에 맞고, LIST 파서가 권한·소유자까지 준다. 직접 구현은 LIST 방언·PASV·TLS 협상까지 다시 만들어야 해 합리적 노력을 넘는다(4-D ⑥) |
| D2 | SFTP 라이브러리 | `ssh2 = "0.9.6"` | 전제 4·5 — 동기 API. 대안 `russh-sftp`는 tokio를 요구해 AGENTS "async 런타임 사용 안 함"을 깬다 |
| D3 | 자격증명 보관 | DPAPI `CryptProtectData` (사용자 범위) | 사용자 확정 + 전제 8. `windows` 크레이트에 기능만 더하면 되어 신규 패키지 0 (4-D ⑤) |
| D4 | 연결 정책 | **기본**: 사이트당 탐색 1 + 전송 2. **사이트 설정의 `최대 동시 연결 수(M)`가 켜져 있으면 그 값이 전체 상한** — 탐색용 1개를 먼저 확보하고 남는 수를 전송에 배정한다. **M=1이면 실제 TCP 연결은 1개이고 탐색 채널이 전송을 겸한다(명령 직렬 처리) — 이때 매니저는 큐에 전송 슬롯을 `1`로 보고한다.** 즉 **큐가 보는 값은 언제나 `max(1, 배정된 전송 채널 수)`**이고, 겸용 여부는 매니저 안에서만 안다(큐·러너는 모른다) | 사용자 확정(FR-37) + FR-45 "값은 실제 연결 동작에 반영된다". **UI만 만들고 T4가 3개 고정이면 FR-45·NFR-11이 성립하지 않는다**(1차 리뷰 M1). 겸용을 큐에 노출하면 `next_for`가 0건을 내주어 **M=1에서 전송이 영구히 시작되지 않는다**(2차 리뷰 M1) — 그래서 겸용 지식을 매니저에 가둔다. 서버가 상한을 거부(421 등)하면 그 연결만 물러나 지수 백오프 재시도 |
| D5 | 원격 계층 위치 | `src/remote/` 신설 (기존 `src/fs/`와 나란히) | AGENTS 계층 규약 — `ui`만 상위. `fs`는 Win32 로컬 파일시스템 전담이라 원격을 섞으면 책임이 흐려진다 |
| D6 | 워커 깨우기 | `remote`가 `Box<dyn Fn() + Send + Sync>` 형태의 **깨우기 콜백**을 주입받는다 | 전제 11 — `remote`는 `ui`(egui)를 모르지만, 콜백을 받으면 `ctx.request_repaint()`를 간접 호출할 수 있어 썸네일이 겪은 "50ms 폴링" 우회가 불필요하다 |
| D7 | 늦은 결과 폐기 | 조회 요청마다 **세대 번호** | `DirLoad`(전제 10)와 같은 기법 — 폴더를 연달아 옮길 때 이전 결과가 화면을 덮어쓰는 것을 막는다 |
| D8 | 탭 소스 표현 | `TabSource { Local(PathBuf), Remote { site: SiteId, path: RemotePath, phase } }` | 전제 9 — 탭이 연결의 단위(README §4)라 소스도 탭에 두는 것이 자연스럽다. 패널 단위로 두면 한 패널에 로컬·원격 탭을 섞을 수 없어 FR-33(모든 패널에서 사이트를 새 탭으로)이 성립하지 않는다 |
| D9 | 원격 경로 타입 | `RemotePath(String)` — POSIX `/` 구분자 전용 | `PathBuf`는 Windows에서 `\`를 구분자로 정규화해 원격 경로를 손상시킨다. `\\?\` 접두 문제(`fs::enumerate::to_extended_pattern`)와 같은 함정의 원격 판 |
| D10 | 원격 항목 표현 | `FileEntry`를 재사용하지 않고 `RemoteEntry` 신설 | `FileEntry.name`은 널 종단 `Vec<u16>`(Win32 정렬 API 공용)이고 `modified`는 FILETIME 원시값이다 — 원격에는 둘 다 맞지 않는다. 대신 **정렬 비교(`panel::file_list::compare_entries`)의 규칙은 공유**하도록 공통 트레이트로 추상화 (4-D 재사용) |

| D12 | 전송 버퍼 | 고정 64KB, 파일 전체 버퍼링 금지 | NFR-12. 전제 6에서 양 프로토콜 다 `Read`/`Write` 스트림이라 가능 |

### T1. 원격 도메인 타입 + 세션 트레이트 [Type D]

- **Design**:
  - **배치**: `src/remote/` — `fs`(로컬 Win32 전담)와 나란한 새 최상위 모듈. `ui`만 상위이므로 `remote`는 `ui`를 모른다 (D5)

    - **`permissions` → `mode`로 바꾼 이유**: 표시용 문자열 하나만 들면 chmod(FR-39)가 쓸 숫자가 없어 두 벌이 된다. 비트를 정본으로 두고 `permissions_string()`이 `rwxr-xr-x`를 만든다.

  - **비추상화 선언**: 프로토콜별 설정 차이(FTP 능동/수동, SFTP 호스트 키)를 트레이트에 올리지 않는다 — 각 구현체가 `SiteRecord`에서 필요한 것만 읽는다. 연결 관리자·전송 큐용 별도 트레이트도 만들지 않는다

### T2. FTP/FTPS 세션 구현 [Type D]

- **Files**: `src/remote/ftp.rs`(신규), `src/remote/mod.rs`, `src/remote/types.rs`
- **Design**:
  - **배치**: `remote::ftp` — `RemoteSession`의 FTP·FTPS 구현
  - **신규 심볼**: `FtpSession` — 평문/TLS 두 스트림을 **열거형 한 겹**으로 감싸 같은 메서드를 노출 / `parse_list_line(&str) -> Option<RemoteEntry>` — `suppaftp::list::File` → `RemoteEntry`(권한 문자열·소유자 조립 포함) / 전송 모드(기본/능동/수동) 적용
    - **구현 중 확정 (원안 대비 3건 — 리뷰가 각각 "기술적으로 타당·수용 가능"으로 판정)**: ① **열거형을 두지 않았다** — `suppaftp`에서 TLS 가능한 스트림 타입(`NativeTlsFtpStream`)은 연결 직후엔 평문이고 `AUTH TLS` 승격에 성공해야 암호화로 바뀐다. 즉 **한 타입이 두 상태를 이미 담아** 열거형을 덧대면 19개 남짓한 메서드마다 같은 갈래를 다시 적을 뿐 동작이 달라지지 않는다(라이브러리 소스로 확인). ② **`parse_list_line`(LIST 전용)과 `parse_mlsd_line`(MLSD 전용)으로 나눴다** — `suppaftp`의 MLSX 파서가 `=` 없는 토큰을 조용히 건너뛰어 **아무 문자열이나 받아들이므로**, LIST 경로를 그쪽에 태우면 깨진 줄이 이름만 있는 가짜 항목으로 살아남아 Acceptance ②가 성립하지 않는다. ③ **PASV 사설 IP 대응을 조건부로 구현** — 라이브러리의 `set_passive_nat_workaround`는 무조건 치환이라 사내망 서버(제어 연결도 사설)까지 깨뜨린다. `passive_stream_builder`를 갈아끼워 **광고 주소가 사설이고 제어 연결이 공인일 때만** 호스트를 바꾼다(포트 유지).
    - **`src/remote/types.rs`는 손대지 않았다** — Files에 있었으나 T1이 이미 필요한 타입을 모두 확정해 변경할 것이 없었다.
  - **의존 방향**: `suppaftp` → `remote::ftp` → `remote::types`
  - **비추상화 선언**: TLS/평문을 `Box<dyn>`으로 나누지 않는다 — 우리 쪽 메서드 표면이 같아 트레이트 객체를 도입할 이유가 없다
- **Acceptance**: ① `parse_list_line`이 Unix 형식·심볼릭 링크(`→ 대상` 원천)·폴더·큰 파일·한글 이름을 옳게 옮긴다(단위 테스트). ② 파싱 실패한 줄은 **그 줄만 건너뛰고 나머지 목록이 유지된다**. ③ `download`/`upload`가 **64KB 버퍼 단위로 진행률 콜백을 부른다** — 200KB 입력에서 콜백 4회 이상(인메모리 스트림으로 검증, 서버 불필요). ④ `FE_TEST_FTP_URL`이 설정된 환경에서만 도는 실서버 왕복 테스트가 있고, 미설정이면 건너뛴 사유를 출력한다(이 테스트에 acceptance를 걸지 않는다 — D25).
- **Edge Cases**: MLSD 미지원 → LIST 폴백 / Windows IIS LIST 방언 / 로그인 실패(530) → `RemoteError::Auth`에 원문 보존 / PASV 응답이 사설 IP → 제어 연결 호스트를 쓴다 / 전송 중 끊김 → **부분 전송 바이트 수를 오류에 담아** 이어받기 가능 / 빈 디렉터리 / 권한 없음(550) / TLS 인증서 불일치.
- **Halt Forecast**: **(ii-b)** 실제 사용자 서버 자격증명이 필요해지면 Halt(테스트는 D25로 서버 없이 성립하므로 정상 경로에서는 발생하지 않는다).

- **Design**:
  - **배치**: `remote::sftp`(세션) + `remote::hostkey`(알려진 호스트 저장소). **확인 대화 UI는 T10**이 만든다 — 여기서는 판정 결과와 결정 채널만 정의한다
  - **구현 중 확정 (원안 대비 4건 — 리뷰가 전부 "허용·정확"으로 판정)**: ① **전송 복사 루프를 `remote::mod.rs`로 올렸다** — T2가 `ftp.rs`에 둔 `pump`/`Pumped`/`TRANSFER_BUFFER`를 SFTP도 그대로 쓰는데, 사본이 둘이면 한쪽만 고쳐졌을 때 NFR-12가 조용히 깨진다. 순수 이동(단위 테스트 3건 포함)이라 `ftp.rs`가 Files에 편입됐다. ② **`..`를 우리가 되돌려 놓는다** — `ssh2::Sftp::readdir`는 `.`과 `..`를 **둘 다** 걸러 내므로(크레이트 소스 확인), 루트가 아닐 때 상위 항목을 다시 넣는다. 관측 결과는 plan대로 "`.` 없음 + `..` 하나"이고 FTP(T2)와도 같다. ③ **라이브러리가 이어 붙인 경로를 쓰지 않는다** — `readdir`가 `PathBuf::join`으로 잇는데 Windows에서 이음매가 `\`가 되어 원격 경로가 손상된다(D9의 함정). 마지막 이름만 떼어 쓰고 경로는 `RemotePath`로 조립한다. ④ **`list()`에 패닉 방어막(`catch_unwind`)** — `ssh2`의 Windows 경로 변환이 `str::from_utf8(..).unwrap()`이라 **UTF-8이 아닌 파일명에서 패닉한다**. 워커 스레드가 죽으면 그 연결이 통째로 사라지므로 오류로 바꿔 돌린다(서버 문자셋 지원 자체는 T16·D23).
  - **`cwd`의 의미**: SFTP에는 작업 디렉터리를 옮기는 명령이 없다 — 갈 수 있는 폴더인지 `stat`으로 확인만 한다.
  - **신규 심볼**: `SftpSession` — `ssh2::Session` + `ssh2::Sftp` 보유 / `KnownHosts` — 호스트·포트 → SHA256 지문 표(`%APPDATA%\FileExplorer\known_hosts.json`), `check()` → `Match`/`Unknown{fingerprint}`/`Changed{old,new}` / `HostKeyDecision{Accept,Reject}` — T10의 대화가 돌려주는 값
  - **의존 방향**: `ssh2` → `remote::sftp` → `remote::{types,hostkey}`
  - **비추상화 선언**: 인증 방식을 트레이트로 열지 않는다 — v1은 비밀번호뿐(Out of Scope)
- **Acceptance**: ① `KnownHosts::check`가 미등록·일치·불일치 3분기를 옳게 판정하고 파일 왕복이 보존된다. ② **지문이 바뀐 호스트는 `Changed`를 내고, 세션이 `Accept` 없이는 진행하지 않는다**(자동 수락 경로가 코드에 없음을 테스트로 고정 — D15). ③ `readdir` 결과에서 `.`은 제거되고 `..`만 목록 규칙대로 남는다. ④ `FE_TEST_SFTP_URL` 설정 시에만 도는 실서버 왕복 테스트(미설정이면 건너뛴 사유 출력, acceptance 대상 아님).
- **Edge Cases**: 비밀번호 인증이 꺼진 서버(keyboard-interactive만) → 사유를 알리고 실패 / 심볼릭 링크 대상 없음 / `perm`이 `None` → 권한 열 빈칸 / 4GB 초과 파일 / 인증 3회 실패 후 서버가 끊음 / **지문 파일 손상 → 전부 미등록으로 보고 다시 묻는다**(조용히 수락하지 않는다).
- **Halt Forecast**: **(ii-a)** `known_hosts.json` 위치를 설정 파일과 같은 폴더로 확정.

  - **절차 기록**: V-5 prefilter 1회차를 BASE_SHA `576b64b`(T0 start)로 호출했는데 그 구간에 위 문서 커밋이 끼어 있어 "Task Files에 없는 신규 파일 14개"로 ESCALATE가 났다. **리뷰어 판정은 정확했고 입력이 틀린 것**이라, BASE를 `b5bedf3`으로 정정해 재호출했다. 이후 task는 **직전 task 완료 커밋(또는 그 task의 `checkpoint: T<N> start`)을 BASE로** 잡는다(중간에 루프 밖 커밋을 끼우지 않는다).
- T1 완료: `src/remote/` 신설 + 도메인 타입·`RemoteSession` 트레이트. 의존성 3건(`suppaftp`·`ssh2`·`windows`의 `Win32_Security_Cryptography`) 추가 후 빌드 확인. 신규 단위 테스트 21개(249→266).
  - **결정(원안 대비 3건, 리뷰가 "기술적 필연"으로 판정)**: `pwd` 추가(초기 원격 경로가 서버 홈이라 없으면 정할 수 없다) / `Charset` 타입을 T16이 아니라 `types.rs`에 배치(`SiteRecord`가 담아야 컴파일된다 — T16은 함수만 추가) / `Progress` 트레이트 추가(계획된 `download`/`upload` 시그니처가 진행률·취소 수단 없이는 성립하지 않는다. 취소를 `report`의 반환값으로 처리해 프로토콜 구현이 취소 방식을 모르게 했다).
  - **결정**: `RemoteEntry`의 권한을 표시 문자열이 아니라 **POSIX 비트(`mode: Option<u32>`)**로 든다 — 문자열만 들면 chmod(FR-39)가 쓸 숫자가 없어 정본이 두 벌이 된다. `permissions_string()`이 `rwxr-xr-x`를 만든다.
  - **quality 리뷰 지적(m1) 반영**: `Encryption::Implicit` 독스트링이 "전용 포트를 쓴다"고 약속했는데 `default_port`는 프로토콜만 보고 21을 준다 — **주석이 동작보다 넓었다.** 포트를 암호화 항목이 몰래 덮어쓰면 사용자가 적어 둔 값이 사라지므로, 동작을 그대로 두고 주석을 사실에 맞췄다(FR-27·T15③과도 정합).
  - **커밋 hook 오탐 확인**: `check-secrets`가 "password 값"을 경고했으나 `password_sealed` 필드명·`login(.., password: &str)` 파라미터명일 뿐 평문 값은 없다(quality 리뷰가 독립 확인).

- T2 완료: `remote::ftp` 신설 — `FtpSession`(연결·인증·목록·전송·파일 작업) + LIST/MLSD 파서 + 오류 분류. 신규 단위 테스트 20개(266→286).
  - **결정**: 전송 복사 루프를 순수 함수 `pump`으로 떼어 냈다 — 서버 없이 64KB 보고·취소·부분 전송 실패를 실측하려면 세션 밖에 있어야 한다(D25). `download`/`upload` 두 곳이 같은 것을 쓴다.
  - **결정**: MLSD는 서버가 **그 사실(fact)을 실제로 준 경우에만** 권한·소유자·시각을 채운다. 라이브러리 파서는 없으면 `0o777`·1970년을 기본값으로 넣는데, 그대로 믿으면 화면이 서버가 하지 않은 말을 한다.
  - **결정**: 이어 올리기는 REST+STOR이 아니라 APPE로 한다 — 업로드에 REST를 받아 주는 서버가 들쭉날쭉하고, 이어받기 지점은 호출부가 원격 파일 크기로 이미 정한다.
  - **의존성**: `suppaftp`에 `deprecated` 기능 플래그 추가(사전 승인 1). 묵시적 TLS 경로(`connect_secure_implicit`)가 그 플래그 뒤에 있어, 없으면 `Encryption::Implicit`이 고를 수 없는 값이 된다.
  - **리뷰 지적(M1) 반영**: plan Edge Case "PASV 응답이 사설 IP → 제어 연결 호스트를 쓴다"가 구현에 없었다. `passive_stream_builder` + 순수 함수 `passive_target`으로 조건부 치환을 넣고 IPv4·IPv6 경계를 테스트로 고정했다(재리뷰 OK).
  - **커밋 hook 오탐 확인**: `check-secrets`가 "password 값"·"IP 주소"를 경고했으나, 앞은 `password: &str` 파라미터명·환경변수에서 읽는 테스트 URL 파서이고 뒤는 RFC 5737 문서용(203.0.113.x·198.51.100.x)·RFC 1918 사설 대역 상수다. 실제 자격증명·인프라 주소는 없다(두 리뷰어가 독립 확인).

- T3 완료: `remote::sftp`(SFTP 세션) + `remote::hostkey`(TOFU 지문 저장소) 신설. 신규 단위 테스트 21개(286→307).
  - **결정**: 지문 확인을 **주입받은 통로**(`HostKeyPrompt`)로 처리한다 — `remote`가 `ui`를 모르는 채로 사용자에게 물으려면 이 방향뿐이고(D6과 같은 기법), **통로가 없으면 거절**이라 자동 수락 경로가 코드에 존재하지 않는다(D15). 판정(`resolve_host_key`)과 파일 저장을 나눠 판정만 단위 테스트로 고정했다 — 저장까지 묶으면 테스트가 사용자 폴더를 건드린다.
  - **결정**: 지문 표기는 `SHA256:` + 패딩 없는 base64(`ssh-keygen -lf`와 같은 표기). 사용자가 서버에서 뽑은 값과 눈으로 대조해야 하므로 표기가 다르면 대조 자체가 안 된다. 이것 하나 때문에 base64 패키지를 들이지 않고 15줄로 직접 넣었다(RFC 4648 시험값으로 고정).
  - **관측(라이브러리 함정 3건, 크레이트 소스로 확인)**: `Sftp::readdir`가 `.`·`..`를 둘 다 걸러 냄 / 항목 경로를 `PathBuf::join`으로 이어 Windows에서 `\`가 섞임(D9 함정) / Windows 경로 변환이 `from_utf8().unwrap()`이라 **비UTF-8 파일명에서 패닉**. 앞의 둘은 우리가 이름만 떼어 쓰고 경로를 직접 조립해 피했고, 셋째는 `catch_unwind`로 막아 연결이 죽지 않게 했다.
  - **커밋 hook 오탐 확인**: `check-secrets`의 "password 값" 경고는 `password: &str` 파라미터명과 환경변수에서 읽는 테스트 URL 파서다.

- T4 완료: `remote::connection`(연결 1개 = 워커 스레드 1개) + `remote::manager`(연결 소유·채널 배정) + `remote::testing`(가짜 서버·세션) 신설. 신규 단위 테스트 25개(307→332).
  - **결정**: 재시도 조건을 "421"이 아니라 **`RemoteError::Connect` 갈래 전체**로 잡았다 — 421도 그 갈래로 분류되고, 일시적 네트워크 실패도 다시 걸면 되는 같은 성격이다. 반대로 인증·호스트 키 실패는 다시 걸어도 같은 답이라 즉시 포기한다.
  - **결정**: 백오프 규칙을 `RetryPolicy`로 **주입 가능**하게 했다. 기본값은 계획대로 1초→2배→최대 30초·5회이고, 테스트는 눈금을 ms로 줄인 정책을 넣어 실제로 31초를 기다리지 않는다.
  - **결정**: `ConnectionManager::open`이 세션을 **만들지 않고 받는다** — SFTP는 호스트 키 확인 통로(T10의 화면)가 필요해서, 관리자가 세션을 조립하면 `remote`가 `ui`를 알아야 한다. (spec 리뷰가 T10에서 "ui는 manager만 만진다"와의 정합을 다시 볼 것으로 남겼다.)
  - **리뷰 지적 2건 반영**: ① 취소 테스트가 **기계 속도에 기대고 있었다** — 큰 파일을 걸어 두고 10ms 뒤 취소하는 방식이라 빠른 디스크에서는 전송이 먼저 끝난다. 응답 없는 서버로 전송을 세워 놓고 **관측된 상태**로 판정하게 바꿨다. ② **백오프 대기 중에는 종료 신호를 못 봤다** — 앱을 닫아도 워커가 최대 30초 소켓을 쥔 채 남는다. `shutdown` 신호를 두고 20ms 단위로 살피며 자게 했다(회귀 테스트 추가).

- T5 완료: `remote::log`(연결별 링 버퍼 2000줄) 신설 + `ConnEvent::Log`가 종류를 싣도록 확장. 신규 단위 테스트 15개(332→347).
  - **결정**: 로그 버퍼를 `Connection`이 들고 `poll()`이 쌓는다(plan Design 그대로) — 워커는 이벤트로 올리기만 하고 화면은 `connection.log()`로 읽기만 한다.
  - **결정**: 시각은 쌓는 시점에 로컬 `HH:MM:SS`로 만든다. Win32 변환쌍(`FileTimeToSystemTime`+`SystemTimeToTzSpecificLocalTime`)을 쓰며 `panel::file_list::format_filetime`과 같은 방식이라 새 Cargo 기능이 필요 없다.
  - **구현 중 자체 발견**: 가리기 판정이 문자열을 **바이트로 잘라** 한글이 섞인 줄에서 패닉했다(로그 대부분이 한글이다). 바이트 비교로 고치고 회귀 테스트를 넣었다.
  - **리뷰 지적 — BLOCKER 2건(둘 다 D14를 실제로 무너뜨리는 것)**: ① 주소 가리기가 `@`를 **앞에서부터** 찾아, 비밀번호에 `@`가 있으면(`p@ss`) 뒷부분이 평문으로 남았다 → 뒤에서부터 찾고 범위를 호스트 부분으로 한정했다. ② **가리기를 버퍼 안에서만 해서 이벤트 채널에는 평문이 실려 나갔다** — 버퍼를 거치지 않고 이벤트를 직접 쓰는 쪽(T20)에 그대로 샌다 → 이벤트를 만드는 지점(`log_event`)으로 옮기고 버퍼의 가리기는 두 번째 문턱으로 남겼다(멱등성 테스트로 고정).
  - **재리뷰 통과 후 추가 정리(MINOR 2건)**: 한 줄에 주소가 여럿이면 첫 번째만 가리던 것을 전부 가리도록 바꿨고, `mask_secrets`를 `pub` → `pub(crate)`로 좁혔다.

- T6 완료: `remote::secret`(DPAPI 봉인) + `remote::sites`(사이트 목록 CRUD·숨기기·비밀번호) 신설. 신규 단위 테스트 16개(347→363). **DPAPI 왕복 테스트는 실제로 암·복호를 실행**한다(가짜 없음).
  - **관측**: `Cargo.toml`은 손대지 않았다 — `Win32_Security_Cryptography` 기능이 T2에서 이미 들어가 있었다(plan Files의 `Cargo.toml`은 그 시점에 이미 해소됨).
  - **결정**: `SiteStore`에 `insert`·`set_password`·`password`·`visible`·`unhide`·`is_hidden`을 함께 두었다 — 세션 복원(T25)과 연결 직전 비밀번호 해제(T4의 `open(site, password, ..)`)가 요구하는 최소 표면이다(리뷰가 T14·T15·T25 근거로 YAGNI 아님 판정).
  - **리뷰 지적(quality MAJOR 2건 — 둘 다 "평문 흔적 제거"라는 이 모듈의 존재 이유를 무너뜨리는 것)**: ① 평문 버퍼를 `fill(0)`으로 지웠는데 **그 뒤로 아무도 읽지 않는 저장이라 최적화가 통째로 지울 수 있다** → 바이트별 `write_volatile` + `compiler_fence`로 바꿨다(소거 전용 패키지를 들이지 않는 최소 구현). ② `String::from_utf8(plain.clone())`이 **실패 경로에서 지울 수 없는 평문 사본**을 남겼다 → 빌려서 읽는 `str::from_utf8`로 바꿔 사본 자체를 만들지 않는다.

- T0~T6 완료. 남은 것: T4~T26 + Phase F + Phase G(PRD 연결 plan).

## Retry Ledger

- T2: 리뷰 지적 수정 사이클 1회(M1 — PASV 사설 IP). 빌드 실패 0회, 복구 0회.
- T6: 리뷰 지적 수정 사이클 1회(quality MAJOR 2 + MINOR 2 동시 수정). 빌드 실패 0회, 테스트 실패 0회.
- T5: 리뷰 지적 수정 사이클 1회(quality BLOCKER 2건 동시 수정) + 재리뷰 통과 후 MINOR 2건 정리. 빌드 실패 0회, 테스트 실패 1회(자체 발견 — 바이트 슬라이싱 패닉).
- T4: 리뷰 지적 수정 사이클 1회(quality MAJOR 2건 동시 수정). 빌드 실패 1회(clippy 루프 형태), 테스트 실패 1회(가정 오류 — 워커가 죽으면 `send`가 실패한다).
- T3: 리뷰 지적 수정 사이클 2회(M1 — `pwd()`의 비보호 패닉 경로 / M1 — follow-up 미기록). 빌드 실패 1회(수명 파라미터), 복구 0회.
  - **절차 기록**: quality 리뷰 1회차가 turn 예산 소진으로 판정 없이 끊겨 `incomplete`로 보고 **재호출로만 해소**했다(자체 판정 금지 규약). 재개 호출이 남은 두 축(사용자 문구·base64 경계)을 마치고 판정을 냈다.
