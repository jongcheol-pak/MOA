# Plan: 폴더 트리 아이콘·즐겨찾기 제목·기본 항목 (2026-08-17)

**PRD**: docs/prd.md

## 요구 이해
- **원문 요청**: "즐겨 찾기 목록위 쪽에 '즐겨 찾기' 문구 표시 / 폴더 트리가 구현되어 있는데 2번이미지(윈도우 탐색기)처럼 폴더명 앞에 폴더 아이콘표시, 드라이브(c:,d: 등) 드라이브 아이콘 및 이름도 같이 표시 / 즐겨 찾기 목록에 '바탕 화면', '다운로드' 목록의 상단에 표시를 하고 해제는 할 수 없음"
- **이해한 요구**: 폴더 트리를 **윈도우 탐색기와 같은 모양**으로 만든다 — ① 즐겨찾기 목록 위에 `즐겨찾기` 제목을 흐린 작은 글씨로 둔다 ② 트리의 모든 줄에 셸 아이콘을 붙이고, 드라이브는 드라이브 아이콘과 함께 **셸 표시 이름**(`로컬 디스크 (C:)`)을 보인다 ③ 즐겨찾기 맨 위에 **바탕 화면·다운로드**를 기본으로 두되 **해제할 수 없다**(그 줄의 우클릭 메뉴에 `해제`가 없다).
- **포함하지 않는 것으로 이해**: 파일 목록(오른쪽)의 아이콘은 이미 있으므로 건드리지 않는다. 기본 항목을 사용자가 늘리거나 바꾸는 설정도 이번 범위가 아니다.

## Goal
폴더 트리가 윈도우 탐색기처럼 아이콘·드라이브 이름을 보이고, 즐겨찾기에는 제목과 기본 바로가기 둘이 선다.

## 시각 정합 판정 (Step 2.5 미발동 근거)

요청이 "탐색기처럼"이라 시각 충실도 요청으로 읽힐 여지가 있으나, **대조 대상이 픽셀 규격이 아니라 두 가지 표시 규칙**(줄마다 셸 아이콘이 붙는가 · 드라이브가 셸 표시 이름으로 보이는가)이라 `## 시각 요소 분해` 표(요소별 속성·픽셀 값)로 분해할 것이 없다. 그 둘은 T2·T3의 acceptance가 직접 판정하고, 아이콘 모양 자체는 **셸이 정하므로 우리가 맞출 값이 아니다**. 색·여백·글꼴 같은 치수 요구는 이번 요청에 없다.

### 4-C. 테스트 파일
- `src/app/favorites.rs`의 `mod tests` — 기본 항목이 앞에 오고 해제되지 않는지, 사용자 항목과 겹칠 때 한 줄만 남는지
- `src/ui/tree.rs`의 `mod tests` — 원격 시험 헬퍼의 `show` 호출 갱신
- `src/ui/panel/tests.rs` — 제목 문구·아이콘 그려짐·드라이브 표시 이름·기본 항목 메뉴에 `해제` 없음.
  **기존 시험 4건이 `"즐겨찾기"` 리터럴을 쓴다**(`:1347·1379·1402·1494`) — D7은 제목과 메뉴를 **가를 수 있는 값**을 만들 뿐 자동으로 고쳐 주지 않으므로, **네 곳의 단언 리터럴을 `즐겨찾기에 담기`로 바꾸는 것까지가 T4의 일이다** — ① `즐겨찾기_줄의_메뉴는_해제다`(`:1378`)는 화면에 `"즐겨찾기"`가 **없어야** 통과한다 ② `트리_노드를_우클릭하면_즐겨찾기_메뉴가_뜬다`(`:1346`)는 제목과 메뉴 줄을 구분하지 못하게 된다 ③ **`이미_담긴_폴더는_즐겨찾기_줄이_비활성이다`의 `pick_on_last_drive`(`:1494`)가 `"즐겨찾기"` 첫 매치로 메뉴 줄 좌표를 잡는다** — 제목이 서면 그 좌표가 제목을 가리키는데, 그 분기는 `picked == None`을 기대하므로 **틀린 자리를 눌러도 통과해 시험이 소리 없이 죽는다**(가장 위험한 축이다) ④ **`원격_트리_노드에는_메뉴가_뜨지_않는다`(`:1402`)는 `text == "즐겨찾기" || text == "해제"`로 담기 메뉴의 회귀를 감시하는데**, 문구를 바꾸면 그 첫 항이 어떤 화면 문자열과도 맞지 않아 **죽은 조건이 된 채 계속 초록**이다.
  **하네스가 기본 항목을 임의로 싣지 않는다** — `FavoriteHarness`·`draw_once_*`는 인자로 받은 항목만 그린다(기본 항목이 필요한 시험만 명시적으로 실어 준다). 하네스가 `with_defaults`로 기본 둘을 자동으로 실으면 `:1347`이 **제목만으로 통과**해 메뉴가 안 떠도 초록이 된다.
  **"메뉴는 트리 폭 밖"이라는 구분은 쓰지 않는다** — 메뉴는 클릭 자리에 뜨고 `clamp_menu_pos`는 뷰포트 안으로만 당기므로, 트리 줄을 우클릭한 메뉴는 `x < TREE_WIDTH` 안에 그려진다(`tree.rs:236·317·576`). 구분은 **D7의 별도 문구**가 맡는다
- `src/fs/icons.rs`의 `mod tests` — 표시 이름 조회(실 드라이브 대상이라 값 자체가 아니라 "빈 문자열이 아니다"로 판정)

## Decisions
### D1. 아이콘을 어디서 얻는가
- **Options**: A) 기존 `IconCache`(셸 이미지 리스트) 재사용 / B) phosphor 아이콘 글꼴 / C) 자체 이미지 리소스
- **Chosen**: A
- **Rationale**: 요구가 "윈도우 탐색기처럼"이므로 **셸이 주는 그 아이콘**이어야 한다(드라이브 종류·네트워크 드라이브가 각각 다르게 보인다). B는 모양이 통일돼 탐색기와 다르고, C는 유지 비용만 는다. 파일 목록이 이미 이미지 리스트를 쓴다.
  **단 기존 `icon_index`를 그대로 쓸 수는 없다** — 그 함수는 `is_dir`을 먼저 걸러 일반 폴더 아이콘을 주므로(전제 1-b) 드라이브가 구분되지 않는다. 그래서 A는 "이미지 리스트·텍스처 인프라 재사용 + 경로 실조회 신규 함수"를 뜻한다
- **Source**: `src/ui/list_details.rs:398-421`(그리기 인프라) · `src/fs/icons.rs:135-141`(기존 조회의 한계)

### D2. 드라이브 표시 이름을 어떻게 얻는가
- **Options**: A) `SHGetFileInfoW`에 `SHGFI_DISPLAYNAME` / B) `GetVolumeInformationW`로 볼륨 레이블을 읽어 직접 조립 / C) 경로 그대로(`C:\`)
- **Chosen**: A
- **Rationale**: 탐색기가 보이는 문자열이 곧 셸 표시 이름이다. B는 `로컬 디스크`·`(C:)` 같은 지역화 조립을 직접 해야 해 언어마다 틀어지고, C는 요구를 만족하지 못한다
- **Source**: 기존 `icons.rs`가 같은 API를 쓰고 있어 unsafe 격리 관례를 그대로 따른다

### D3. 기본 즐겨찾기 경로를 어떻게 얻는가
- **Options**: A) `SHGetKnownFolderPath`(FOLDERID_Desktop·FOLDERID_Downloads) / B) `%USERPROFILE%\Desktop` 등 문자열 조합
- **Chosen**: A
- **Rationale**: 사용자가 바탕 화면·다운로드를 다른 드라이브로 옮길 수 있어 B는 틀린 경로를 가리킬 수 있다. 표시 이름(`바탕 화면`)도 셸에서 얻어야 지역화가 맞는다
- **Source**: 전제 4·5

### D4. 기본 항목을 저장소에 어떻게 담는가
- **Options**: A) `FavoriteStore`가 기본 항목을 **따로 들고**(저장 대상 아님) 사용자 목록 앞에 붙여 준다 / B) 시작할 때 사용자 목록에 밀어 넣는다 / C) 화면(트리)이 매번 앞에 끼워 그린다
- **Chosen**: A
- **Rationale**: B는 저장 파일에 기본 항목이 섞여 다음 실행에 중복되고, 나중에 기본 목록이 바뀌면 옛 항목이 사용자 것처럼 남는다. C는 "해제 불가" 판정이 화면에 흩어져 시험으로 덮기 어렵다. A는 판정(`can_remove`)이 순수 계층에 모여 시험에 걸린다
- **Source**: 위키 conventions — 판정 로직은 `ExplorerApp` 밖 타입에 둬야 검증된다

### D5. 없는 기본 폴더의 처리
- **Options**: A) 시작할 때 존재를 확인해 없으면 목록에서 뺀다 / B) 항상 보이고 누르면 실패 안내
- **Chosen**: A (사용자 결정)
- **Rationale**: 누를 수 없는 줄이 고정으로 남는 것보다 낫다. 확인은 **시작 시 두 경로뿐**이라 창 뜨는 시간에 영향이 없다(트리 전체를 훑는 것이 아니다)

### D6. 트리 줄 그리기의 공통화
- **Options**: A) 즐겨찾기·잎 노드·펼침 노드의 줄 그리기를 헬퍼 하나로 모은다 / B) 각자 두고 아이콘 코드만 세 번 쓴다
- **Chosen**: A
- **Rationale**: 이번에 아이콘이 더해지면 같은 모양이 **세 곳**이 되어 공통화 문턱(3회)을 넘는다 — 대장에 등재된 SUGGEST의 재검토 조건이 바로 이것이다. 각자 두면 다음 변경 때 한 곳만 고쳐 줄마다 모양이 갈린다
- **Source**: `docs/plans/deferred.md`의 2026-08-17 SUGGEST 항목

### D7. 제목 문구를 메뉴 항목과 같은 값으로 둘 것인가
- **Options**: A) 제목도 `즐겨찾기`(메뉴 항목과 같은 리터럴) / B) 제목을 `즐겨찾기`로 두되 시험은 출현 횟수·y좌표로 가른다 / C) **제목 문구를 메뉴와 다른 값으로 둔다**(예: 제목 `즐겨찾기`, 메뉴 항목 `즐겨찾기에 담기`)
- **Chosen**: C
- **Rationale**: A는 화면 문자열만으로 제목과 메뉴를 가를 수 없어 **기존 시험 3건이 깨지거나 조용히 죽는다**(4-C ③이 그 사례 — 틀린 자리를 눌러도 통과한다). B는 시험을 출현 횟수·좌표로 정교하게 만들어야 하는데, 그 정교함이 다음 변경 때 다시 깨질 자리다. C는 **화면에서도 낫다** — 제목은 구역 이름이고 메뉴는 동작이라 원래 다른 말이어야 한다(`해제`가 이미 동작 어휘다).
  사용자 요구는 "'즐겨 찾기' 문구 표시"이므로 **제목이 `즐겨찾기`인 것은 그대로 지키고**, 바꾸는 것은 메뉴 항목 쪽이다
- **Source**: `src/ui/panel/tests.rs:1346·1378·1494`(충돌 지점) · `src/i18n/mod.rs:196`(`tree_favorite_add => "즐겨찾기"`)

### D8. 해제할 수 없는 줄의 우클릭
- **Options**: A) 메뉴를 열되 `해제` 줄을 비활성으로 그린다 / B) 메뉴를 열되 항목이 없어 빈 상자가 뜬다 / C) **메뉴를 아예 열지 않는다**
- **Chosen**: C
- **Rationale**: B는 눌러도 아무 일이 없는 빈 상자라 가장 나쁘다. A는 "왜 안 되는지"를 알려 주는 장점이 있지만, 기본 항목은 **원래 뺄 수 없는 자리**라 매번 비활성 줄을 보이는 것은 소음이다(트리 노드 쪽 `즐겨찾기` 비활성은 "담을 수 있었는데 이미 담겼다"는 상태 안내라 성격이 다르다). C는 관측도 명확하다 — 메뉴 프레임이 그려지지 않는 것을 시험이 그대로 단언한다
- **Source**: `src/ui/tree.rs:257-261`(현재 `MenuTarget::Favorite`은 언제나 `해제` 한 줄)

### D9. 아이콘 캐시가 실제로 듣는지 검증하는 방법 (사용자 승인 2026-08-17)
- **Options**: A) `IconCache`에 시험 전용 조회 카운터를 두고 "같은 경로 2회 요청 → 셸 조회 1회"를 단언 / B) 캐시 acceptance를 빼고 성능은 수동 확인 / C) 아이콘 기능 자체를 이번 범위에서 제외
- **Chosen**: A (사용자 선택)
- **Rationale**: 아이콘 조회는 **끊긴 네트워크 드라이브에서 UI를 초 단위로 멈출 수 있는 실경로 I/O**라 "한 번만 조회한다"가 성능의 전제다. 맵 크기(`len`)로는 이것을 관측할 수 없고(키가 같아 다시 조회해도 크기가 그대로), 검증이 없으면 **캐시가 죽어도 시험이 초록인 상태**가 굳는다. 비용은 `#[cfg(test)]` 필드 하나와 시험 1건뿐이다
- **Source**: 리뷰 2라운드 M1(RECURRING) — 1라운드의 맵 크기 판정이 관측력이 없다는 지적
